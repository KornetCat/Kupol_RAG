# RAG-агент Купола с веб-интерфейсом

Локальное приложение непрерывно принимает телеметрию, сопоставляет связанные подсистемы, извлекает инструкции и исторические эпизоды, передаёт свидетельства в DeepSeek и исполняет только разрешённые проверенные действия. Ручные указания человека проходят через DeepSeek и имеют приоритет над конфликтующим автоматическим решением. Аппаратные защиты и права API сохраняют приоритет.

## Быстрый запуск

1. Распакуйте весь комплект. Переносимая сборка Windows x64 уже содержит Python и зависимости; установка не требуется. Для архива исходников нужен Python 3.11 или новее.
2. Если используете исходный `Dome_RAG-main.zip` с ключами команды 4, положите его рядом с `start_web.py`. Ключи также можно задать в окружении или полях подключения; они остаются в памяти процесса.
3. Запустите `start_web.cmd`. В переносимой сборке он сразу использует комплектный Python. В архиве исходников подготовит локальную `.venv` и установит зависимости; для этой первой установки нужен интернет.
4. Откройте `http://127.0.0.1:8080`, введите актуальный адрес Купола (`IP:порт`, `ws://...` или `wss://...`) и нажмите «Подключить».
5. Остановка приложения — Ctrl+C в консоли. Кнопка «Отключить» завершает сетевую сессию Купола.

Памятка для площадки — `ONSITE_START.txt`. В переносимой сборке все CLI-команды из примеров также доступны: замените `python` на `runtime\python\python.exe`. `start_agent.cmd`, `check_dome.cmd` и `emergency_light.cmd` автоматически используют этот же комплектный Python.

```powershell
python -m pip install -r requirements.txt
python start_web.py
python start_web.py --port 8081 --no-open
python start_web.py --config config.example.json --context context.example.json
```

Веб-интерфейс доступен только на этом компьютере. Адрес Купола не зашит в веб-приложение и не сохраняется браузером. Заданный `DOME_URL` позволяет подключаться автоматически после запуска. Ключи не входят в распространяемый комплект. `.env.example` — образец переменных, а не файл с готовыми значениями; приложение само не загружает `.env`.

## Как работает RAG

1. Один читатель WebSocket принимает сообщения и сопоставляет `request_id`. Обновление экрана и первичная реакция на опасность не ждут DeepSeek.
2. Код проверяет возраст, доступность и согласованность данных, зависимости питания, задержки источников и изменения во времени. Учитывается округление времени узла до миллисекунд.
3. Поисковый запрос дополняется аномалиями, именами сигналов и связанными подсистемами. BM25, метаданные состояния и баланс категорий выбирают технические инструкции, разные исторические эпизоды и подтверждённый опыт; дубли эпизода не заполняют весь контекст.
4. При неоднозначной выдаче DeepSeek дополнительно ранжирует только найденные кандидаты. Затем DeepSeek получает выбранные свидетельства и текущие данные для диагноза и выбора сценария. Другие LLM и модели эмбеддингов не используются.
5. Исполнитель независимо проверяет актуальный каталог, роль, свежую телеметрию, допустимость действия и ручной приоритет. ACK отделяется от проверки результата.
6. Источники, выбранный сценарий, действие, ответ API и проверка результата попадают в журнал. История и документы являются данными без исполнительных полномочий.

Историческая база построена из [WhiteDots/Dome_RAG](https://github.com/WhiteDots/Dome_RAG), ревизия `a16da2db079cdcb395e354383199effdf5a170b2`: семь дней, 10 080 кадров, 2 478 событий и 111 эпизодов. У каждого эпизода есть происхождение: файл, SHA-256, строка и время. Исчезновение симптома после команды не объявляется доказанным ремонтом. Подробности — `docs/HISTORY_ANALYSIS.md`.

Оценка поиска и её ограничения — `docs/retrieval_evaluation.md`; воспроизвести локальную оценку можно командой `python -m kupol_agent.retrieval_eval`. Это небольшой размеченный набор, а не гарантия качества на неизвестных кризисах.

## Ручной приоритет и автоматические реакции

В чате есть два режима. «Разовый запрос» — вопрос или команда, которая обрабатывается один раз. Такой текст не сохраняется в руководящих указаниях, не оставляет постоянный приоритет и не передаётся в историю последующих запросов модели. «Указание на будущее» сохраняется в отдельном доверенном контексте DeepSeek до явного снятия кнопкой и само по себе сейчас не запускает оборудование. Скрытого срока действия у сохранённых указаний нет.

Неотправленные устаревшие планы отменяются при новом ручном запросе. Уже отправленную команду нельзя отменить задним числом: агент сверяет её результат и фиксирует неопределённость при потере связи. Технический журнал решений, запросов API и результатов сохраняется в обоих режимах для проверяемости по регламенту; запись аудита не является будущей инструкцией агенту.

Ручные команды доступны и в тренировочном, и в соревновательном профиле. Они не отменяют проверки безопасности, права активной команды или аппаратные блокировки. Физические операции из `operator_controls` не имитируются программными командами.

На странице «Телеметрия» есть отдельная панель «Прямое управление через API»: выберите узел, действие и значение. Этот явно выбранный ручной путь работает без вызова DeepSeek, выполняет одну команду и не создаёт указание на будущее. Доступны только проверенные действия текущего каталога; исполнитель повторно проверяет роль, свежесть данных и защиты. Передача G-code выполняется через отдельную форму. Панель различает ответ API, подтверждённое новое состояние и неопределённый результат; слепого повтора нет.

Автоматическая диагностика работает сразу. Первичная подготовка автоматического исполнения доступна в веб-интерфейсе: задайте проверенные для объекта минимальные потоки вытяжки, притока и охлаждения и подтвердите безопасное состояние текущего подключения. Числовые критерии сохраняются, разрешение исполнения относится к текущей сессии. Затем включите переключатель автоматического реагирования. Редактировать JSON-файлы для этого не требуется; после переподключения разрешение нужно подтвердить заново. Проверки потоков, текущих прав, свежих показаний и блокировок сохранены. Пустые физические минимумы не подменяются значениями из виртуальных тестов.

Библиотека содержит 15 сценариев. Автоматическое исполнение ограничено включением вытяжки, притока, охлаждения и изменением режима/скорости притока при выполнении предусловий. Другие кризисы получают RAG-диагноз, проверки и эскалацию. Модель не расширяет этот список и не сбрасывает защиты. Разделение на 10 пересекающихся подсистем задано в `kupol_agent/data/subsystems.json`.

При дыме или аварийной остановке действует немедленная программная фиксация опасности, запрещающая дальнейшие команды. Она сохраняется через перезапуск. Возобновление требует разрешения ответственного и подтверждённого безопасного состояния по инструктажу; интерфейс не выдаёт такое разрешение автоматически. После разрешённого устранения причины подготовьте корректный контекст и снимите локальную фиксацию `data/safety.json` перед повторным запуском. Это не сбрасывает аппаратные блокировки API.

## Файлы и производственные задания

- Загружаются готовые G-code файлы организаторов: UTF-8, `.gcode`, `.nc`, `.tap`, `.ngc`, до 16 МиБ. Бинарные модели STL и архивы не принимаются. Источник файла декларируется пользователем в форме.
- DeepSeek получает имя, размер, SHA-256, целевой узел и выбранные параметры для проверки операции. Сам G-code в контекст модели не передаётся. При согласованном плане исходный текст файла уходит напрямую в API выбранного станка.
- Загрузка и запуск — разные действия. Загрузка никогда не запускает станок автоматически.
- Принтер объявляет `upload_file`. Для фрезера опубликованный API предоставляет `list_files` и `start_job`; загрузка доступна только если текущий `describe_nodes` также объявит `upload_file`.
- Для запуска выберите серверный файл и нажмите «Запустить выбранный файл» либо дайте указание в чате. Запуск проходит через RAG/DeepSeek и проверку текущей готовности станка. Файл фрезера с `valid:false` не запускается.
- Ответ API, наличие файла в списке, переход станка в рабочее состояние и фактическое изготовление детали — разные уровни подтверждения.

## DeepSeek и регламент

В системе есть только клиент DeepSeek. По последнему указанию пользователя оба профиля используют доступный по ключу `deepseek-flash`; проверка точной версии V4/V4.1 не блокирует работу. Фактически обслуженная модель записывается в журнал. `DEEPSEEK_FINAL_MODEL` и `DEEPSEEK_FINAL_SERVED_MODEL` остаются необязательными настройками для явной фиксации модели; без них достаточно рабочего ключа.

В предоставленном PDF п. 10.6 назван V4 Flash. Пользователь разрешил использовать доступную версию, поэтому внутреннее ограничение снято. Это изменение настройки приложения не изменяет текст регламента; отличие отражено в матрице требований.

Настройки и матрица требований — `docs/REGULATION_COMPLIANCE.md`. Шаблон декларации — `docs/AGENT_DECLARATION_TEMPLATE.md`. Если организаторы предоставят отдельный DeepSeek endpoint, его адрес и разрешённую модель нужно явно закрепить в конфигурации.

## Память, журналы и перезапуск

SQLite хранит инциденты, попытки и результаты отдельно по средам. `VERIFIED_SUCCESS` автоматического ремонта требует реального исполнения, минимум двух разных свежих наблюдений и устойчивого эффекта; ACK и replay этого не доказывают. Это обучение через поиск и статистику, а не дообучение весов DeepSeek.

Ранний рост тока вентилятора при неизменном режиме сохраняется отдельно как `OBSERVED_TREND_UNCONFIRMED`. Это наблюдение, без объявления поломки или успешного ремонта. После исчезновения предупреждения и перезапуска оно доступно поиску RAG в своей среде; текущую аварийность агент оценивает по свежим данным. Хранятся только ограниченный числовой ряд и рабочий контекст, без команд и новых полномочий.

Реальный ручной опыт аварийного освещения с подтверждением пользователя сохранён в `kupol_agent/knowledge/field_experience/` и машинной записи `kupol_agent/data/field_experience/`. Он не подменяет более строгую проверку автоматических ремонтов.

JSONL-журналы сохраняют начало/остановку, подключения, диагноз, ссылки RAG, вызовы DeepSeek, решения, команды, ответы и проверку результата. Записи сразу сбрасываются на диск. Ключи удаляются; вместо содержимого загружаемого G-code журнал содержит размер и SHA-256. Неопределённая команда после обрыва связи не повторяется вслепую.

Один исполнитель блокирует параллельное управление из второго процесса с тем же хранилищем. Локальный веб-интерфейс использует отдельную сессию, проверку Origin/Host и токен для изменяющих запросов. Ключи не отправляются браузеру обратно и не сохраняются в localStorage.

## CLI и проверки

```powershell
python -m kupol_agent demo --db data/demo.sqlite
python -m kupol_agent analyze --input telemetry.json
python -m kupol_agent replay --input telemetry.jsonl --limit 100
python -m kupol_agent search --query "нет потока вытяжки, питание линии включено"
python -m kupol_agent memory --limit 20
python -m unittest discover -s tests -v
python tests/test_stress.py
python scripts/probe_precursor_memory.py --after
python scripts/run_generated_crisis.py
python scripts/run_novel_stress.py
```

Два скрипта кризисных сценариев используют официальный API DeepSeek и ключ команды 4 из исходного архива; исполнитель и телеметрия в них локальные синтетические. Они не подключаются к Куполу и сохраняют результаты отдельно в `output/`. Остальные перечисленные тесты не вызывают внешнюю модель и не управляют оборудованием.

Консольный `start_agent.cmd` сохранён. Отдельные утилиты `check_dome.cmd` и `emergency_light.cmd` предназначены для ручных проверок; актуальный адрес передавайте через `--address`.

Тесты используют локальные фиктивные транспорты. Предоставленный виртуальный Купол проверяется отдельно: подключение команды 4, живой поток и справочные ответы DeepSeek. Полная приёмка кризисов и производственных команд требует отдельных испытаний сценариев; доступность сервера её не заменяет. Испытание аварийного освещения в предыдущем сеансе не является проверкой всех остальных устройств.

Для цифрового двойника используйте отдельное хранилище, например `python start_web.py --data-dir data/digital_twin`. Реальную смену запускайте с отдельным `data/real_dome`, чтобы виртуальные результаты не попадали в статистику физического контура.
