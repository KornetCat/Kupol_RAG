# Декларация RAG-агента Купола — шаблон

- Команда: 4.
- Название: kupol-rag-agent.
- Версия: 0.4.0; перед игрой дополнить точным Git commit / SHA-256 архива.
- Модель: доступный по ключу deepseek-flash; указать фактически обслуженный ID из журнала. Точная фиксация версии в приложении необязательна по запросу пользователя; отличие от буквального п. 10.6 PDF отражено в матрице требований.
- Данные: текущая разрешённая телеметрия/каталог, документация API, исторические эпизоды из публичных логов, локальная память подтверждённых результатов, явные указания оператора.
- Интерфейсы: WebSocket API Купола, разрешённый API DeepSeek, локальный веб-интерфейс на loopback.

## Функции

1. Непрерывный приём телеметрии и выявление прямых, ложных и каскадных признаков.
2. Поиск по связанным подсистемам, документации, историческим кризисам и опыту; DeepSeek анализирует найденные свидетельства и актуальное состояние.
3. Исполнение проверенных автоматических сценариев в пределах конфигурации и прав; отдельная обработка постоянных указаний через DeepSeek, разовых команд чата и прямых ручных команд API. Постоянные указания приоритетнее конфликтующего автоматического плана; все пути исполнения проверяют текущие права и безопасность.
4. Передача разрешённых организаторами текстовых G-code файлов по объявленному API; выбор файла и запуск задания являются разными операциями.
5. Проверка результата и журналирование. Обучение на случаях через RAG и статистику, без дообучения весов модели.

## Границы автономности

Перечислить фактически включённые runbook_id, их версии и критерии результата из конфигурации. Не включать в декларацию неактивные или неиспытанные действия. Самостоятельная модификация защит, доверия датчиков, физических порогов и состава разрешённых команд отсутствует. Физические действия оператора через программные controls не имитируются.

## Подтверждения и резерв

Указать, какие действия выполняются по явному указанию человека и какие полномочия подтверждаются до старта. При опасности применяются инструкции площадки и штатная аварийная остановка. При потере связи, невозможности проверить состояние или неопределённом результате команда не повторяется вслепую; агент сообщает ограничение, сохраняет журнал и переходит к сверке/наблюдению.

Перед подачей дополнить: утверждённые минимальные потоки, независимость источников датчиков, инструкции после аварийной остановки, разрешённые файлы производства, результат проверки на цифровом двойнике/стенде, ответственных участников.
