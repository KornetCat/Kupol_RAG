# Контекстный поиск RAG: устройство и оценка

`HybridRetriever.retrieve(query, environment, limit=8, *, telemetry=None, faults=None)`
совместим с прежними вызовами. Он использует только локальные алгоритмы для
поиска: BM25, простую нормализацию русских окончаний, словарь терминов API,
структуру пересекающихся подсистем и RRF. Другой модели эмбеддингов нет.

Сначала собирается расширенный запрос с целевыми узлами, сигналами и
предположительными классами неисправности. Числа переводятся в дескрипторы
для сравнения похожих состояний: например, задержанное измерение CO₂ и
нормальное текущее измерение различаются. Эти дескрипторы влияют только на
ранг источника и не являются порогами разрешения команд. Противоречивые и
неполные свидетельства сохраняются, а не исключаются из поиска.

У исторических эпизодов есть компактная сводка, идентификатор эпизода,
ссылки на строки исходных журналов, ревизия и явный статус недоказанной
причинности ремонта. Один эпизод не занимает несколько мест выдачи.
Индекс сохраняет категории справочников, сценариев, истории, рассказов
людей и проверенных случаев из SQLite. Баланс категорий и ограничение
повторных фрагментов одного источника уменьшают вытеснение полезной
инструкции похожими JSON-снимками. Идентификатор чанка не зависит от
абсолютного пути установки проекта.

Для неоднозначной выдачи доступен `needs_rerank(hits)` и
`rerank(query, hits, planner)`. Дополнительное ранжирование использует
только официальный API DeepSeek и уже найденные идентификаторы. Строгая
проверка принимает исключительно перестановку этих идентификаторов.
Новые источники и действия модель создать не может. При ошибке остаётся
локальная выдача. Кэш ограничен 64 запросами; изменения кандидатов,
версии источника и структурного соответствия меняют ключ. Метаданные
последнего вызова находятся в `last_rerank_info` для журнала агента.

## Воспроизводимая локальная оценка

```powershell
python -m kupol_agent.retrieval_eval --out output/retrieval_eval.json
```

Разметка находится в `kupol_agent/data/retrieval_eval_queries.json`.
Это небольшой диагностический набор из 10 вопросов по реальным источникам
ревизии `a16da2db079cdcb395e354383199effdf5a170b2`: четыре development-вопроса
и шесть вопросов, зафиксированных до измерения heldout-набора. Вопросы
перефразированы и не копируют заголовки эпизодов. Значения входной
телеметрии — сконструированные варианты наблюдавшихся состояний, а не
новые реальные измерения. Ожидаемые результаты — стабильные идентификаторы
источников и эпизодов, со ссылками на исходные строки, а не совпадение
строки запроса с самой собой.

Покрыты короткая дымовая тревога между минутными снимками, складской пожар,
несинхронные и одновременно высокие CO₂-показания, E09, ложное завершение
печати по webhook, мигание линии 6, загрязнение притока, дефицит энергии
и отказ вентилятора инвертора. Последний случай специально проверяет
поиск подходящего человеческого дневника и технического справочника,
когда отдельного машинного эпизода в manifest нет. Рассказ при этом не
превращается в доказанную причину.

Оценка сравнивает прежний BM25 по исходным чанкам без сводок, расширенный
поиск без текущего контекста и поиск с телеметрией/неисправностями.
Внешних модельных вызовов при оценке нет. Метрики: Hit@5, Recall@5 по
множеству размеченных источников и MRR@5 по первому релевантному источнику.

Первый запуск 26.10.2026 дал на шести heldout-вопросах:

| Поиск | Hit@5 | Recall@5 | MRR@5 |
|---|---:|---:|---:|
| Прежний BM25 | 0.333 | 0.333 | 0.250 |
| Расширенный, без live-контекста | 1.000 | 0.917 | 0.700 |
| Контекстный | 1.000 | 0.917 | 0.867 |

Это авторская разметка по просмотренным источникам, пока без независимого
арбитража. Набор мал, кейсы не независимы, а показатели не доказывают
универсальную оптимальность, правильность диагноза или безопасность
исполнения. Для следующей оценки нужны отдельная проверка разметки
человеком, новые дни/инциденты без подстройки правил под тест, негативные
примеры без релевантной истории, измерение задержки и отдельная оценка
DeepSeek-переранжирования на том же замороженном наборе. Gates и проверка
эффекта по новой телеметрии остаются самостоятельными механизмами.


## Внешняя проверка условного отбора через DeepSeek

После фиксации локальной реализации выполнен отдельный прогон шести heldout-запросов через официальный API DeepSeek, ID deepseek-flash, с ключом команды 4. Кандидатный пул - 8, измерение - первые 5. Эталонные ID и оценки в prompt не передавались. Условный ранкер вызван только для двух неоднозначных вопросов; оба ответа прошли проверку строгой перестановки ID. Остальные четыре вопроса использовали локальный порядок. Команд Куполу и передачи G-code не было.

На одном и том же пуле до/после: Hit@5 0.833 → 1.000; Recall@5 0.833 → 0.917; MRR@5 0.833 → 1.000. Два запроса использовали 6 785 входных и 651 выходной токен. Неоднозначный вопрос вентилятора инвертора переместил нужный источник с позиции за пределами первой пятёрки на первое место. Полные результаты - docs/retrieval_deepseek_eval.json.

Это отдельная проверка с candidate_pool=8; локальная таблица выше измеряет retrieval limit=5, поэтому её промежуточные contextual-метрики могут отличаться из-за баланса категорий. Не следует смешивать эти два режима или объявлять по шести авторски размеченным вопросам универсальную точность. Истинность диагноза, физический эффект и безопасность действия этими метриками не измеряются.
