# Настройки автоуправления и источники значений

В предоставленном регламенте, документации API и справочниках нет числовых нормативов для трёх критериев результата:

| Поле приложения | Что описано в API | Числовой минимум |
|---|---|---|
| `min_airflow_pct` | `fume_extraction_01.airflow_pct` | Не указан |
| `min_supply_flow_m3_h` | `supply_ventilation_01.airflow_m3_h`, `fresh_air_m3_h` | Не указан |
| `min_cooling_flow_l_min` | `equipment_cooling_01.coolant_flow_l_min` | Не указан |

Источники: регламент §9.1 требует работающую вытяжку при соответствующих работах; `knowledge/reference/01_API.md` описывает поля и разрешённые действия этих трёх узлов. Диапазон команды `supply_ventilation_01.set_speed` 10–100 % — допустимая скорость, а не норматив расхода в м³/ч.

В `config.example.json` эти три значения оставлены `null`. Подменять норматив текущим измерением, средним из исторических логов или придуманным числом нельзя. Минимумы следует получить из паспорта установки, технологической карты или от организаторов, затем задать в форме «Настройка автоуправления».

Остальные стартовые настройки приложения уже соответствуют `Config`: возраст данных 15 с, задержка измерения 5 с, минимум два наблюдения результата за 8 с, тайм-аут проверки 40 с. Это настройки приложения; они не объявляются физическими нормативами оборудования. Порог CO₂ 2000 ppm соответствует описанию `IL_CO2` в API; аппаратная уставка этим не изменяется.

Сохранение критериев не включает автоуправление. Подтверждение безопасности относится к текущему подключению и отзывается при его потере. Разовые команды, чат, файлы, телеметрия и диагностика остаются доступны в пределах текущих прав и проверок.
