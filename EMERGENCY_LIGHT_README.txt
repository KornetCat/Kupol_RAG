РУЧНОЕ УПРАВЛЕНИЕ АВАРИЙНЫМ ОСВЕЩЕНИЕМ КУПОЛА

1. Подключите компьютер к локальной сети Купола.
2. Распакуйте весь комплект. Нужен Python 3.11 или новее.
3. Положите исходный Dome_RAG-main.zip рядом с emergency_light.py,
   чтобы прочитать ключ команды 4. Иначе программа запросит ключ скрытым вводом.
4. Дважды нажмите emergency_light.cmd и выберите действие:
   1 — включить, 2 — выключить, 3 — только показать состояние.

Адрес по умолчанию: ws://192.168.8.126:8766.
При заданной переменной DOME_URL используется её адрес; --address имеет приоритет.

Управление выполняется через smart_panel_01, линия 7 «Аварийное освещение»:
line_on — включить, line_off — выключить, value: 7.
После команды скрипт проверяет новое состояние по свежей телеметрии.
Скрипт отправляет не более одной управляющей команды за запуск.

Запуск из PowerShell в папке комплекта:

  .\emergency_light.cmd --state on
  .\emergency_light.cmd --state off
  .\emergency_light.cmd --state status
  .\emergency_light.cmd --address 192.168.8.126:8766 --state on
  .\emergency_light.cmd --address wss://janus-server.a.2na.am:443 --state status

Ключ DOME_KEY из окружения имеет приоритет над ключом из архива.
Другой архив и команда задаются через --keys-archive и --team.
Ключ команды 4 в комплект не включён и в отчёты не записывается.

Результаты каждого запуска сохраняются в output/emergency_light/<время>/:

  result.txt  — состояние до и после, результат или причина ошибки;
  result.json — тот же отчёт в JSON.

Ответ API о принятии команды сам по себе не означает, что свет переключился:
для подтверждения нужна новая телеметрия. При потере связи команда вслепую
не повторяется. Скрипт не сбрасывает защиты линии и не обходит блокировки.

При наличии каталога _vendor с websockets дополнительная установка не нужна.
Иначе launcher установит зависимость из интернета при первом запуске.
Локальное окружение Python .venv создаётся автоматически.

Все параметры: python emergency_light.py --help
