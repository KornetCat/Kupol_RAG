Это запись наблюдений для RAG, а не инструкция к исполнению. Тип результата: HUMAN_CONFIRMED_SUCCESS. Пользователь подтвердил: «Включение и выключение аварийного освещения прошло успешно».

## Проверенная конфигурация

Адрес сервера задаётся при подключении и может меняться. Постоянный IP не является частью этого опыта. Авторизация: team, команда 4. Актуальные адрес, порт, конфигурацию и права проверяют при следующем подключении.

## Успешные действия

Включение 26.10.2026, 19:31:45–19:31:49 по Москве: control smart_panel_01 line_on value=7. До OFF, после ON. Выключение 19:32:14–19:32:20: control smart_panel_01 line_off value=7. До ON, после OFF. Для каждого действия сохранён положительный ответ API и один новый кадр состояния; физический результат обоих действий отдельно подтвердил пользователь. Последнее наблюдение этого сеанса — OFF, а не гарантия текущего состояния в будущем.

## Причина первоначальной ошибки и исправление

Скрипт подключался, но не отправлял control: строгая проверка свежести молча отклоняла кадры. timestamp=1793032234.7407467, updated_at=1793032234.741: второй показатель округлён до миллисекунд и выглядит примерно на 0.000253 с новее кадра. Проверка 0 <= timestamp - updated_at ошибочна для такого округления. В emergency_light.py введён допуск -0.001 <= timestamp - updated_at <= 15. Это допуск точности времени, а не разрешение использовать старые данные. Сохранены online=true, status=OK, локальный возраст получения <=5 с и отдельная новая телеметрия после команды. Основной engine.py содержит аналогичное строгое сравнение; учитывать при его следующем улучшении.

## Особенности измерений и границы опыта

В ON и OFF сервер показывал одинаковое voltage_v=239.2, current_a=0 и power_w=0. Эти величины сами по себе не подтверждают свечение или отсутствие свечения ламп. Свидетельства разделены: ACK API, переход поля state и подтверждение человека. Результат ручной проверки не доказывает устойчивость автоматического сценария и не меняет автоматические полномочия. Два кадра после каждого действия не сохранялись: не создавать такую историю задним числом и не переносить случай в статистику SQLite VERIFIED_SUCCESS с вымышленными наблюдениями.

Одна явно выбранная команда за запуск, без автоматического повтора и без сбросов защит. Проверять line по идентификатору, назначение по актуальному названию, действие по свежему describe_nodes. Выводить этапы подключения, авторизации, отправки и проверки результата; показывать конкретную причину отклонения телеметрии.
